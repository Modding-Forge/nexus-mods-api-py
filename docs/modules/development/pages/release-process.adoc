= Release process

Build one universal `py3-none-any` wheel and one source distribution. CI installs the same
wheel on supported Windows, Linux, and macOS architectures. Releases use PyPI Trusted
Publishing from a protected environment and are never initiated by local development.
Artifact validation requires the wheel's typing marker and license plus the source
distribution's README, license, documentation descriptor, pinned OpenAPI snapshot, and
generation tooling.

The required matrix covers Python 3.11 through 3.14 on Windows Server 2025 x64,
Ubuntu 24.04 x64 and ARM64, and macOS 15 on ARM64 and Intel. Python 3.14 additionally
checks Windows Server 2022 x64, Ubuntu 22.04 x64 and ARM64, macOS 14 ARM64, and macOS 26
on ARM64 and Intel. Windows 11 ARM64 and Ubuntu 26.04 x64 and ARM64 are non-blocking while
their GitHub-hosted runner images remain in public preview. All jobs install the same
universal wheel; the project does not create misleading platform-specific copies.

== One-time publishing configuration

Create a protected GitHub environment named `pypi` and require a maintainer review for
deployments. Then register a pending GitHub Trusted Publisher in PyPI with these exact
values:

* PyPI project name: `nexus-mods-api`
* Owner: `Modding-Forge`
* Repository name: `nexus-mods-api-py`
* Workflow name: `release.yml`
* Environment name: `pypi`

The project name must match the `project.name` value in `pyproject.toml` exactly. Trusted
Publishing uses a short-lived OpenID Connect identity, so no PyPI API token or password
belongs in GitHub secrets.

The repository's `pypi` GitHub environment must require designated reviewers. The release
workflow performs the complete CI and cross-platform package matrix first, then pauses at
that environment for manual approval. It authenticates to PyPI exclusively through OpenID
Connect Trusted Publishing; no long-lived PyPI token is stored.

Every release tag must exactly match the package version with a `v` prefix, for example
`v1.2.0`. Manual workflow runs require the same version value. The workflow rejects a
tag or input that differs from either the project metadata or the public package version.
Tag-triggered releases also create a GitHub release containing the verified universal
wheel and source distribution.

Manual API key, WebSocket SSO, and OAuth each passed local live acceptance on 2026-08-01
using the maintainer's own registered Nexus Mods application credentials. Repeat the
affected live flow after authentication or protocol changes. The current release is
`1.2.0`.
