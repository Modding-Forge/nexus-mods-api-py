= Credential storage

The library deliberately provides no secret store. It keeps credentials in memory and
invokes an optional credential callback after refresh. Applications must choose a storage
mechanism appropriate to their platform and threat model.

Store the access token, rotating refresh token, expiry, and optional fingerprint together.
Replace stored credentials atomically after every callback. Never log raw API keys, OAuth
codes, PKCE verifiers, access tokens, refresh tokens, fingerprints, or callback URLs.
